What a person sees and touches has a plugin of its own.

The standards, the patterns and the design skill, stated before any stack is chosen.

spn-surface is the plugin a repository that builds a page loads beside spn-apps, and this page reads it one folder at a time. Read it before you add a rule about how a page looks or behaves, or when you want to know why the design skill is not in the apps plugin. It says only what is in this domain, and sends you to the page that states each part in full.

Overview

A page is chosen and drawn before it is built, and the rules for choosing it are true of every stack: what a label says, which container holds a panel, which pattern a task follows. spn-surface carries those rules. Each folder here is the same kind of instrument spn-devex defines.

This page is for a UX designer or a web developer working on a page, and for anyone about to add a Surface rule. It assumes you know what a plugin is; if you do not, the spn-devex overview comes first. After it you know which folder a change belongs in, and why this plugin names no stack.

The one thing to unlearn is that the design belongs with the code. How a block is built in TypeScript is the apps plugin's. What the block is called, when it is used and how its page is arranged is this plugin's. This plugin ships no agents and no providers, and it has no chapter for either.

What you can decide after this page. Whether a rule is about what a person sees or about how a stack builds it, and which plugin it then belongs in.

The Plugin — what spn-surface is, and when a session loads it

Everything this domain ships sits in one folder, and that folder is what an install copies. Its identity is its own: the name and the description in its manifest say what it carries, and the description is what a session matches against when it decides whether to load the plugin at all. Its version reads 0.1.0, the number its first release publishes.

Hooks — one moment, for the connector's script

This plugin wires one moment: the call about to hand a script to the Figma connector. The connector refuses some of what it is given and throws on the rest, and either answer arrives after the call, so the one rule here reads the script before it. Every other call a session makes never reaches this plugin.

Decide here: whether a new rule is about a script's text before the connector runs it, and so belongs on this moment.

Skills — the command a Surface question answers to

The design skill states a page, a screen or a flow as a tree of named blocks, in the order the Surface standards decide things: the person, the flow, the pattern, the panels, the tasks, and only then the blocks. It writes no code. Where the window holds the Figma connector it can draw the tree, and where it holds none the tree is still complete.

Decide here: whether a new request is a design question, and which step of the skill it reaches.

Scripts — the code this plugin runs

The folder divides by what calls each file. The wiring starts one process, which asks the connector check and returns one verdict. The command line ships no command today. The helpers a check needs, the masker, the text a write would leave and the stack read, have one copy in the shared support folder, so no plugin reads a neighbour's file.

Decide here: whether a new piece of code is a check the dispatcher asks, or a helper another plugin also needs.

Refs — the Surface book, restated inside the plugin

A partner holding this plugin has no copy of the foundation book beside it, so the Surface rules are written out inside it: the standards, the patterns, the architecture of the design system, its library and its delivery. Two folders of skeleton specs are copies the book owns. A ref states and never executes, and each one says which version of the book it was read at.

Decide here: whether a fact the design skill needs is a restatement of the book, and where in the mirror it goes.

Read Refs →

Tests — the plugin's own folders, without a framework

This plugin runs a rule on a person's design file, so it owes proof of its own. Its suites sit at the plugin root under one tier, mirror the source, and are found by walking. The bundle a hook runs is held to its source twice: it must answer what the source answers, and it must not be older than the source.
