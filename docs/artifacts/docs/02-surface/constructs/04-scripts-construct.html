Scripts

Every file this plugin runs, sorted by what calls it.

Scripts holds everything this plugin executes, divided by what calls each file: the entry the wiring names, the check it asks, the command line a person types, and the libraries the others read from the shared support folder. Read this page to see what runs, what reads what, and which files this plugin does not own.

Overview

Today the plugin runs three checks:

  • the connector check;
  • the Surface check;
  • the read advice.

The command line ships three commands:

  • check scan reads Surface code whole for every note the check gives.
  • unit find names the units a task's words point to.
  • unit show prints one unit from the CONSTRUCT snapshot the plugin carries, or a unit beyond the core from the symbol index of the repository it runs in, or, from a workspace's root, of each repository in it.

--repo narrows either lookup to one repository. The entry refuses an unknown group by name, and a command added later is a file under commands/ and reachable as soon as it exists. The helpers a check needs, the masker that blanks comments and strings, the text a pending write would leave, and the stack of the repository that owns a path, live in the shared support folder and are bundled into each plugin that reads them, so no plugin reads a neighbour's file.

This construct realizes the book's 01-devex/02-agent/04-plugins.

Model

  1. A call reaches the dispatcher through the wiring.
  2. The dispatcher asks the check.
  3. The check reads the library.
  4. The library is copied into the bundle.

Parts

Dispatcher — The dispatcher runs the chain and never takes it down

The first refusal wins and stops the chain, because a refusal is an answer. Warnings accumulate, because two pieces of advice are better than one. A check that throws is skipped, never fatal.

Own file — A check keeps its own file and can run alone

Each check exports a verdict function and can be run by hand against a payload on stdin, so a verdict from the dispatcher is the verdict the check gives alone.

Shared timer — The timer is the shared one, bundled in

The dispatcher records its run through the shared timing library, which writes only while the developer has asked for it and can never fail a gate.

Shared helpers — The shared helpers have one copy

The masker, the resulting text and the stack read are one copy each in the shared support folder, proven there once. This plugin imports them by relative path; the build copies them into its own bundle.

Bare name — The command line is typed by its bare name

A launcher under bin/ puts the plugin's entry on the Bash tool's path while the plugin is enabled, and tiers.json declares the permission tier of each command group: check and unit, both allowed.

Unit lookup — The unit lookup reads the plugin, and the repository's index for a unit beyond the core

spn-surface unit show <Unit> prints one unit for the agent that designs or builds a page. Its props, its usage, its index by value and the units their place sizes come from refs/support/surface/construct.snapshot.json, the CONSTRUCT snapshot written from the book of each release.

Its cases come from the unit's restated table in architecture-components.md or architecture-widgets.md, because the snapshot keeps only the cases that draw the unit, and a case such as not a sheet: a DSDialog draws nothing. A partner holds the plugin and not the book, so the command never opens the book, a sibling checkout or the machine's home folder. Its second line names the book's release the snapshot was written from. A unit the snapshot does not hold, the design system's own or a module's, has no table in the book, so its props and their descriptions carry its use: the command reads them from the symbol index of the repository it runs in, .claude/saasplane/spn-symbols.json found from the working folder upwards, else each package's own dist/generated/spn-symbols.json under packages/* and apps/*, and never from source.

A fresh window starts at the workspace root, which is no repository, so there it reads the merged index of each member instead — a member is a child folder with a sprepo.json, and they are read in name order — and the line it prints names the member. A name several members carry comes from the first whose entry carries props, because a member may pin a release of a package whose index was written before props were read from the code, and a line under it names the others.

--repo <name or path> reads one repository alone, a member's name or a path inside one, from anywhere (RULE.DEVEX.AGENT.112). It then names the core block the unit's last word points to, whose table decides what the props do not (RULE.SUPPORT.APPS.207). Source and bundle sit three folders under the plugin's src/, so one relative path serves both.

spn-surface unit find <words…> names a unit before unit show prints it. An ask names a task, not a unit, and unit show takes a name, so a window given no name searched the source for the task's words and read the file it found. unit find is that search over what unit show reads and nothing else: the snapshot's core units and the symbol index's components, of the repository it runs in or, from a workspace's root, of each member, or of the one --repo names. A unit is matched by its name, split at each capital, and by its line or intent; a word matches by its first five letters, so verified finds Verification, and a word of three letters or fewer is dropped. A unit ranks by how many of the words it carries, then by its name carrying them rather than its line, and the first eight print, each with its package, its repository and the core block its name points to.

Lookup first — A Read of a unit's file is advised to run the lookup first

A unit's file is named for the unit, so a Read of ForgotPasswordStep.tsx under a module's src/entry/ui/ or the design system's src/ui/ is a read of the unit ForgotPasswordStep. The read advice puts a note beside that Read, naming spn-surface unit show ForgotPasswordStep and saying to read the source only for what it leaves out. Three rounds of asks found a module's unit by reading its source, because the design skill's words never reached the window at that moment; the note stands beside the call it is about. It advises and never refuses, since a window may need what the index does not carry, and it decides from the path's text alone. A search gets no note: its words name a task, and unit find answers those.
