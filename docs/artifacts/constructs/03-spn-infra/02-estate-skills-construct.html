Estate Skills — The Verbs That Change an Estate

An estate is changed by editing what it declares itself to be, and then by letting a tool render and apply that declaration. The verbs here cover that walk: saying what the estate is, reading what a change would render before anybody approves it, writing a new piece for the estate to run, and publishing a piece that is finished.

They share one boundary, and each of them restates it. No verb here changes a cloud. Each names the tool verb that does, and the caution the workspace states everywhere — a cloud is changed only through the tool's own doors — is repeated rather than worked around.

Model

Each verb is a different point on one walk, and the last box is the same for all of them.

None of these folders divides into steps: each walk is short enough that one file holds it.

Parts

Declaring is a manifest edit, reviewed line by line

A change to what the estate is should read as one line per choice. A diff mixing rendered output with declared intent hides the decision inside the consequence. So the declaring verb changes the manifest, validates it, and shows the difference in that shape. Authoring a new package and publishing one are explicitly not this verb, and its description names both neighbours so a wrong ask lands in the right folder. Where: plugins/spn-infra/skills/declare/SKILL.md

A rendering is read before anything is approved

Approval is the last moment a wrong rendering is cheap. After it, the estate has changed. So one verb states what a rendering must name and what it must never contain, and it also answers the narrower question of whether a declaration change produced exactly what was intended and nothing more. It is convened before any approval, never after. Where: plugins/spn-infra/skills/plan-review/SKILL.md

Authoring a module names what is not a module

A vendor reached over the network is application configuration behind a seam, and the estate never sees it. Treating one as a module builds infrastructure for something that does not exist. So the authoring verb covers a piece the platform actually runs, and rules the networked case out in the sentence a session matches against. It walks the whole path in one file, from the first scaffold to the pin flip. Where: plugins/spn-infra/skills/module-author/SKILL.md

The version is a reviewed edit, and the tool verb does the rest

A version typed into a build script is a second place the number lives. The package manifest is the one place. So the publishing verb edits that field as a reviewed change and then runs the release verb, which stages and publishes. The same verb covers repointing a bespoke script at the release verb, so the second place stops existing. Where: plugins/spn-infra/skills/release/SKILL.md

A verb names the card, and the card holds the words

None of these files defines the estate's vocabulary. Each names the card that does — which file declares what, which layer owns which act, how a name is composed — so a verb sequences the work and the card holds the words. Where: plugins/spn-infra/refs/

Boundary

This page answers which verbs an estate repository answers to and what each one does. It does not answer what a skill is — the frontmatter, the matching and the rule that a skill carries steps and never a rule are The Skill. It does not answer the vocabulary these verbs use either, and it does not answer what happens at write time when an edit would break a law.
