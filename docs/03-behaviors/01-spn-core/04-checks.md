# Behaviors — The Check

`For: Backend developer · Architect` · `Status: 🔮 PLANNING`

[The Check](../../02-constructs/01-spn-devex/04-checks.md) makes the promises below. A row says what somebody can do and what they see when they do it.

Every row below is declared and none is claimed: a run writes the last two cells.

| Id | Who | Does | Sees | Type | Tier | Status | Updated at |
| --- | --- | --- | --- | --- | --- | --- | --- |
| MKT.CHECK.01 | Backend developer | make an ordinary edit and pay almost nothing for the gates | A check that cannot have an opinion about the path is never asked to read anything | POSITIVE | UNIT | PLANNED | — |
| MKT.CHECK.02 | DevSecOps / Security | be refused any route that would render the machine seat | The whole command is read, a quoted path inside a here-document included, and the message names the door | NEGATIVE | UNIT | PLANNED | — |
| MKT.CHECK.03 | Backend developer | be refused a state write that would close a loop | The folder is read with the pending write laid over it, so the graph judged is the one the write would make | NEGATIVE | UNIT | PLANNED | — |
| MKT.CHECK.04 | Backend developer | write many files in one turn and read a warning once | A speaking check remembers what it said and does not repeat it in the same session | POSITIVE | UNIT | PLANNED | — |
| MKT.CHECK.05 | Architect | be told which document governs the folder being edited | The longest governing folder wins, and a folder no row governs is answered with silence | POSITIVE | UNIT | PLANNED | — |
| MKT.CHECK.06 | Engineering leader | close a scope with work pending and still pass | Landed, carried and deferred all pass, and only a row nobody decided is refused | POSITIVE | UNIT | PLANNED | — |
| MKT.CHECK.07 | Editor | have a document measured against a stated bar rather than against the corpus average | The numbers come from the register row, and headings, tables, code and metadata are removed first | POSITIVE | UNIT | PLANNED | — |
