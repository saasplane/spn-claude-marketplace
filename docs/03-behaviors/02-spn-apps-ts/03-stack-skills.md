# Behaviors — Stack Skills

`For: Backend developer · Web developer` · `Status: 🔮 PLANNING`

These are the promises [Stack Skills](../../02-constructs/02-spn-apps-ts/03-stack-skills.md) makes. A row says what somebody can do and what they see when they do it.

Every row below is declared and none is claimed: a run writes the last two cells.

| Id | Who | Does | Sees | Type | Tier | Status | Updated at |
| --- | --- | --- | --- | --- | --- | --- | --- |
| MKT.TSSKILL.01 | Backend developer | build a capability in an order that does not have to be undone | The contract step is read before the service, and each step before that layer's code | POSITIVE | UNIT | PLANNED | — |
| MKT.TSSKILL.02 | Web developer | make a front-end change without walking the server steps | The ask is classified first, and the classification decides which steps apply | POSITIVE | UNIT | PLANNED | — |
| MKT.TSSKILL.03 | Backend developer | ask for a review and get the mode the ask meant | Each skill names its modes in the sentence a session matches against | POSITIVE | UNIT | PLANNED | — |
| MKT.TSSKILL.04 | Backend developer | learn a mode is destructive before it runs | The reset mode is marked destructive in the description rather than only in the body | NEGATIVE | UNIT | PLANNED | — |
| MKT.TSSKILL.05 | Architect | copy from a step file and get the rules with it | The steps carrying rules carry them under a stamp, and cite their chapters otherwise | POSITIVE | UNIT | PLANNED | — |
| MKT.TSSKILL.06 | Engineering leader | have a contract change reviewed by something that did not write it | The build skill closes with the suites and hands the change to the review skill | POSITIVE | UNIT | PLANNED | — |
| MKT.TSSKILL.07 | Architect | plan in a stack repository without a second planning skill competing | Planning stays in the core plugin, and this plugin ships only the layer it reads | NEGATIVE | UNIT | PLANNED | — |
