# Personas — The Functions The Plugins Serve

`For: Engineering leader · Architect · Backend developer · Web developer · Quality engineer · DevOps / SRE · DevSecOps / Security · Partner / integrator · Editor` · `Status: 🔮 PLANNING`

A behaviour is only meaningful once you know whose outcome it is. **Every `Who` cell in this repository's [behaviour rows](README.md) resolves here**, and a persona is invented nowhere else. That is the drift this one table exists to stop: where each area names its own people, the same person arrives twice under two words and no check can see it.

**This repository ships no product, so its people are the ones who meet the plugins.** What it ships is three plugins — the hooks that refuse a write, the checks that read a repository, the tools somebody runs by name, the skills a session loads, and the refs and lenses a review is argued from. The people who meet those are the engineering functions of whatever team installs them.

So the personas below are **the lens register's own functions** — the closed set [the lens construct](../02-constructs/01-devex/03-agents.md) defines, which is also the set a document declares as its audience. Each one is a role this repository's model already names, so nothing here is a new word. Nine of the register's twelve functions name a row today; the three that name none are listed at the end.

| Actor | Who they are | What the rows promise them |
| --- | --- | --- |
| **Architect** | Shapes the plugin set and the review procedure — the person who decides what a skill is, which document governs a folder, and how far a reviewer's authority reaches | That the plugin set is readable from one file, that a broken gate does not take the rest of the chain down, that a job takes a folder wherever it would take a file, that a produced page's links land where the seat file meant, and that a viewpoint fallen behind the book is reported rather than trusted |
| **Backend developer** | Builds in a TypeScript repository with the plugins installed, and meets them on every turn — the hooks at write time, the checks on demand, the skills a session loads | That an install leaves every wired path resolving, that a window opens with the ground already read, that a refusal reaches the agent rather than only the developer's pane, that a rule answers the same at write time and in a sweep, and that an ordinary edit pays almost nothing for the gates |
| **Engineering leader** | Owns the release and the standard of review — the person who has to know which bytes a session is running and who read the work | That a review is convened from a context which did not write the work, that it reports rather than edits as it reads, that a finding is told apart from a suggestion, that work stops on a stated threshold rather than on taste, and that no report arrives unasked |
| **DevOps / SRE** | Runs the estate and authors what plugs into it — the person who declares an environment, reads a plan, and takes a module from its first scaffold to its pin | That a change to what the estate is reads as one line per choice, that what a change would render is readable before anybody approves it, that a layer which will not start can be diagnosed from the order alone, that a package version lives in one place, and that the guard keeps working when it cannot read its own input |
| **Editor** | Writes and maintains the corpus — the person who scores a paragraph, produces a page, draws a diagram, and keeps a restatement honest against the chapter it came from | That the readability numbers come from the register row rather than from the tool, that a page is produced from its seat file and never typed, that a diagram is measured from its own text and then checked as drawn, and that a stamp is re-read against the chapter as it stands today, per citation |
| **DevSecOps / Security** | Assures what the plugins may do — the person who has to know that a door cannot be walked around and that a refusal is never a crash | That estate caution is enforced at the moment a write would land, with the law named in the message; that the whole command is read, a quoted path inside a here-document included; that a delegated brief is bound by the tools it declares; and that every path exits zero, so a refusal is a printed decision rather than a failure code |
| **Quality engineer** | Proves behaviour, and owns what a run is allowed to say about it — the person who reads a results file back onto the rows | That the rows are joined from the register beside the construct without the seat file being touched, that a run writes only the status and the moment it was found, that it writes only rows declaring a tier it covered, and that a row a person checked by hand is never written over |
| **Partner / integrator** | Reads the standards from outside the team, having been granted nothing | That the whole marketplace is public and publishing it is pushing the repository, that a restatement carries its chapter's content and cites the chapter by name, and that the renderer covers the seat file's grammar while pulling in no dependency |
| **Web developer** | Builds web surfaces in a repository with the plugins installed | Five rows today. A host is compared as a parsed host rather than matched inside a longer string. A journey assertion with a trailing comma and no message gets its note. An ask is classified before any step runs, so the classification decides which steps apply. A page is designed as a tree of named blocks, in a window with a Figma connector or with none |

**Three of the register's functions name no row here.** A UX designer is one of them: the rows of the `design` skill name the Web developer, who runs it. A business manager and a product manager are consumers of a platform built on these standards, not of the plugins themselves — nothing this repository ships promises either of them an outcome. They keep their place in the lens register, because a document may still declare them as its audience, and they will earn a row here the day a plugin does something a person in one of those functions can observe.

**No persona carries a list of the rows that name it.** The join already knows which rows name which persona, and a list of ids typed by hand is the kind of thing that goes wrong without anybody noticing.
