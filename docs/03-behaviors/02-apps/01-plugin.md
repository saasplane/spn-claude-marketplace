# Behaviors — The Plugin

`For: Architect · Engineering leader` · `Status: 🔮 PLANNING`

The table below lists the promises [The Plugin](../../02-constructs/02-apps/01-plugin.md) makes. A row says what somebody can do and what they see when they do it.

Every row below is declared and none is claimed: a run writes the last two cells.

| Id | Who | Does | Sees | Type | Tier | Status | Updated at |
| --- | --- | --- | --- | --- | --- | --- | --- |
| MKT.PLUGINS.01 | Backend developer | reach this domain's material without knowing the plugin exists | The manifest's description is matched against the work at hand, and what it names is loaded | POSITIVE | UNIT | PLANNED | — |
| MKT.PLUGINS.02 | Architect | get this plugin in a repository that answers to the apps world, and not elsewhere | The plugin set is derived from the repository's own manifest rather than typed into a workspace | POSITIVE | UNIT | PLANNED | — |
| MKT.PLUGINS.03 | Engineering leader | answer *are you current?* from one number | Every plugin in this marketplace carries the same version, and a release moves all of them | POSITIVE | UNIT | PLANNED | — |
| MKT.PLUGINS.04 | Backend developer | tell what is published from what somebody is working on | The version names the released bytes; the first edit after a release moves the number | POSITIVE | UNIT | PLANNED | — |
| MKT.PLUGINS.05 | Backend developer | be spared a plugin installing silently over its own published bytes | A cache directory is keyed by version, so an increment is what makes the installed copy findable | NEGATIVE | UNIT | PLANNED | — |
| MKT.PLUGINS.06 | Architect | tell a folder this plugin does not ship from one that is unfinished | No agents folder exists here, because a persona answers to no stack and lives once in the core plugin | NEGATIVE | UNIT | PLANNED | — |
