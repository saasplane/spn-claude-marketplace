# Behaviors — Refs

`For: Backend developer · Architect` · `Status: 🔮 PLANNING`

The table below lists the promises [Refs](../../02-constructs/02-apps/05-refs.md) makes. A row says what somebody can do and what they see when they do it.

Every row below is declared and none is claimed: a run writes the last two cells.

| Id | Who | Does | Sees | Type | Tier | Status | Updated at |
| --- | --- | --- | --- | --- | --- | --- | --- |
| MKT.REFS.09 | Partner / integrator | read a rule this plugin needs with no copy of the book beside them | Every ref is a self-contained leaf, written out rather than linked to | POSITIVE | UNIT | PLANNED | — |
| MKT.REFS.10 | Architect | find where a restatement belongs without being told | The top of the tree holds one folder per book domain, and nothing else is allowed a place | POSITIVE | UNIT | PLANNED | — |
| MKT.REFS.11 | Backend developer | open a folder and learn its subject rather than its contents | A folder's face is about the folder, never a listing of what sits inside it | POSITIVE | UNIT | PLANNED | — |
| MKT.REFS.12 | Architect | compare two stacks question by question | Every stack answers the same questions under the same file names, so the listing is the coverage | POSITIVE | UNIT | PLANNED | — |
| MKT.REFS.13 | Architect | tell a stack this plugin describes from one it does not | A stack with no capability for a question writes the file anyway and says what to do instead | NEGATIVE | UNIT | PLANNED | — |
| MKT.REFS.14 | Editor | be told when a restatement has fallen behind the chapter it copies | Each ref carries the chapters it restates and the hash last read from each, and a run compares them | NEGATIVE | UNIT | PLANNED | — |
| MKT.REFS.15 | Partner / integrator | trust the list of packages a node may depend on after a release | That one file is written by a command and carries the citation naming it, so re-running the command checks it | POSITIVE | UNIT | PLANNED | — |
| MKT.REFS.16 | Backend developer | look for a procedure and not find one here | A ref states what is true; what a skill performs lives under the provider for the stack | NEGATIVE | UNIT | PLANNED | — |
