Every Block, Once

The one source of the sample-block section every page template carries — each block kind and each figure kind shown once, so an author can see the whole vocabulary before choosing.

Writing a page takes two files: the page template for the kind you are writing, which carries its masthead and its sections, and this page, which carries what every kind shares. Open both. This is a reference you consult, never a file you copy — and it is an HTML vocabulary: a markdown seat file keeps markdown's own components, and the renderer gives each one the form you see here.

Normal content — no block, and no ceremony

Most of a page is this: paragraphs, lists, numbered steps and subheadings, written plainly and marked as nothing at all. A block is not how you write a section. It is what you drop into the writing when something must not read as prose. So start here, and reach for a block only when the content has a shape of its own.

The three rules

One outermost container, and it is the thing being described. Anything outside it is something the thing talks to, so a reader sees what is yours before reading a label. Inside it, boxes are grouped into layers that run one way — the direction a call travels — so the direction is learned once and never again. An edge is a call or data, and it carries what flows; an unlabelled line meaning related is the one thing this kind refuses.

It is a MAP with those three rules added, so the drawer is unchanged. MAP keeps its own job: the parts of one thing, where there is no inside and no order.

a server module — read the layers from the bottom: config, the environment it is started with, then app, then entry. Each door is met by the thing that knocks on it, and services and repositories are what reach outside

a web module — the same skeleton, drawn to the same coordinates as the server above. Read it from the bottom too: config, then app, then entry

an estate package — the same skeleton again. Here the layers are containment rather than call order, and it still reads from the bottom: what is declared, then what runs, then what is reachable
