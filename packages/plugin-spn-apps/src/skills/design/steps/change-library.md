# Step: change-library — a change of a library file, through the connector

Read this step when the library lacks a block, a property or a value, the work is a connector write and not a plan, and the window holds the Figma connector. **Every rule is stated in `refs/support/surface/delivery-library.md`, under the heading each line names.** A line here says what to do, and the heading says why and how far it holds. Read the heading before you do the line.

Its provenance is the foundation book's design library chapter. Apply this restatement. The chapter is provenance, and not a file to open.

## The walk, in order

1. **Read the file once, or take the inventory you were handed, and write the time of the reading on it.** Heading: "How the connector's work is carried out", and "How an agent changes a library file through the connector", under "What the agent reads and keeps".
2. **Ask the developer for a named version before the first change in the file, and wait.** Heading: "A developer's hands are three, and you change the library in one of two ways".
3. **Check the order against the live file, and against the web's file and line, and say what you corrected.** Heading: "Before the change".
4. **Tell the developer what is about to change, item by item.** Heading: "A developer's hands are three, and you change the library in one of two ways".
5. **Send one script for each page, given the nodes it may touch, and let it check before it moves anything and return its own proof.** Headings: "During the change", and "How the connector's work is carried out".
6. **Where a call moves versions, read the default version of each set before and after, check it against the stack's default at the top left, and correct a label that disagrees, never follow it.** Heading: "The default version is the stack's default, and the label tells the truth about it".
7. **Give a new set, sheet or page the form of its neighbours, place a case as instances of the unit, and say on the sheet's label what a unit cannot hold, and list it.** Headings: "A new set, sheet or page takes the form of its neighbours", "A sheet of cases, and a case", "A unit that cannot hold the web's case", and "A unit with no look of its own".
8. **Take one picture for each set or sheet, and look at it.** Headings: "How the connector's work is carried out", and "What the agent reads and keeps".
9. **Scan the whole file last.** Heading: "Before a publish".
10. **Tell the developer what changed, what still differs from the web and was left, and that the publish is theirs.** Heading: "Before a publish".

Keep the inventory current as you go: a change to the file updates the inventory's lines for what it changed.

**The connector cannot publish a library, and it never does.** The developer publishes after your word.
